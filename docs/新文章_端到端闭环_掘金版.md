# Agent 安全的完整闭环：发布前扫产物，运行时断行为链

> 发布平台：掘金 / 知乎 / CSDN ｜ 本文为产品介绍，技术细节已脱敏

两个场景：

**场景一（运行时）**：客服 Agent 收到「帮我查退款」，却执行了 `读短信 → 发验证码`——一句话的工夫，验证码出去了。
**场景二（发布前）**：App 上线前，没人发现内置 SDK 在偷偷上传用户数据。

这对应 Agent 安全的两道闸门——**发布前扫产物、运行时断行为链**。缺一道就有洞。

## 第一道闸门：一基三翼（发布前产物合规）

本地直扫 PE / ELF / APK，政企 / 开发者 / 游戏三套规则翼，对标等保、SBOM、GDK。原则很朴素：**证据没拿到就如实说「没拿到」，绝不替客户写「通过」证明**——这是它和普通扫描器的区别。

## 第二道闸门：星环行为链判定（运行时）

发布前的合规扫不出「运行时才会发生的事」。所以判「行为」，不判「单步」：

> 单个动作可能没问题，一串动作连起来可能就是攻击。

### 有序 + 无序，两种维度互补

- **有序判定**：识别动作的先后因果。「先读短信、后发验证码」即使中间夹了正常动作，也能识别出来。
- **无序判定**：只要两个动作凑在一起就危险，不管谁先谁后，同现即判。

两者互补：**有序抓因果，无序兜底**——比只看单步、或只做无序匹配的防护，更精确也更能覆盖真实攻击链。

## 为什么选星环？三大护城河

1. **判行为，不判文本**：文本审核拦不住「读短信→发验证码」，我们直接切断动作链。
2. **系统级底牌**：做行为链判定、且具备底层系统拦截能力的，市面几乎为零。
3. **极致坦诚**：172/172 攻击拦截、0 误伤（有合法对照）。且明确告诉你：**我们不做内容审核（识别率 0%），请继续用 Lakera / Azure，我们是它们下游的终极闸门。**
