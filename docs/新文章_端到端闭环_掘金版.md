# Agent 安全的完整闭环：发布前扫产物，运行时断行为链

> 发布平台：掘金 / 知乎 / CSDN
> 说明：本文为产品介绍，技术实现细节已脱敏（保护后续专利申报）。

---

先看两个场景。

**场景一（运行时）**：一个客服 Agent，用户只说「帮我查退款」，内容审核看完全安全。然后它的工具调用日志是：

```
read_sms          ← 读用户短信
send_credentials  ← 把验证码发出去
```

一句话的工夫，验证码出去了。

**场景二（发布前）**：一个 App 上线前，没人发现它内置的某 SDK 在偷偷上传用户数据。等发现时，它已经在应用市场跑了几周。

这两个场景，对应 Agent 安全的**两道闸门**——发布前扫产物、运行时断行为链。缺一道，就有洞。

---

## 第一道闸门：一基三翼（发布前产物合规自检）

「一基三翼」是一个本地文件直扫的合规自检产品，解决「产物里藏着什么」的问题。

面向三类客户，各有对应的规则翼：

- **政企**：等保 2.0 / 关基 / 信创对标
- **开发者**：SBOM / 许可证 / 构建链
- **游戏**：GDK 合规 / 反作弊完整性

PC 端扫 PE / ELF / Mach-O，移动端扫 APK / DEX。**全程离线**，报告可复核。

它的原则很朴素：**证据没拿到，就如实说「没拿到」，绝不替客户写「通过」的证明**——这是它和普通扫描器最大的区别。

## 第二道闸门：星环行为链判定（运行时）

但发布前的合规**扫不出「运行时才会发生的事」**——一个 Agent 被诱导着把验证码发出去，这不是产物问题，是行为问题。

所以有了第二道闸门：**判「行为」，不判「单步」**。

一句话说清它的能力边界：

> 一个动作单独看可能没问题，但一串动作连起来可能就是攻击。我们判的是「这一串动作想干什么」。

```
read_sms → send_credentials      →  拦截
read_docs("../../etc/passwd")    →  拦截
正常的多步业务操作                →  放行
```

## 四层架构：一套内核，端到端闭环

- **系统级兜底**：在系统底层拦截越权 / 外泄 / 自修改，不依赖大模型自我对齐；
- **行为链判定**：抓「每一步都合法，串起来要命」的链式攻击，含多 Agent 协同场景；
- **极简交付**：SDK / CLI / 本地自测包，10 行代码接入，纯离线跨平台；
- **可复现背书**：177 条高仿真红队样本，跨进程复测逐字节一致，结论经得起复查。

## 为什么选星环？三大护城河

1. **判行为，不判文本**：文本审核拦不住「读短信→发验证码」，我们直接切断动作链。
2. **系统级底牌**：市面上做行为链判定、且具备底层系统拦截能力的，几乎为零。
3. **极致坦诚与确定性**：172/172 攻击全拦截，0% 误伤率（有合法对照）。且我们明确告诉你：**我们不做内容审核（识别率 0%），请继续用 Lakera / Azure，我们是它们下游的终极闸门。**
