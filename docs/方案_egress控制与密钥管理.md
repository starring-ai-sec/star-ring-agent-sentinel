# egress 控制与密钥管理 · 产品与技术方案

> 星环AI行为安全实验室 ｜ 2026-11
> 定位：环境层（底座）的深化——「数据出不去 + 凭据碰不到」的底层兜底
> 治理理念：**判定（识别外发/凭据访问）→ 熔断（阻断）→ 引导（引导走安全通道）**

---

## 一、为什么做 egress + 密钥管理

行为链判定管「该不该做这个动作」，但**「动作合法、数据越界」的场景，需要底层兜底**：

```
场景 1（egress）：Agent 读文件（合法）→ 上传外部（伪装"备份"）→ 行为链能拦，但若被绕过，数据已出网
场景 2（密钥）：Agent 读 .env（参数闸门能拦）→ 但若凭据本身散落在明文里，拦了这一步，下一步还能漏
```

**环境层是最后一道物理闸门**——即使上层判定全部失守，底座还能让「数据出不去、凭据碰不到」。

## 二、三层治理：判定 → 熔断 → 引导

### egress 控制（网络出口）

```
数据外发请求
   ↓
【① 判定】egress 意图：这个外发是否在契约允许的出口白名单内？
   ├─ 白名单内 → 放行
   └─ 白名单外 → 进入熔断+引导
        ↓
【② 熔断】阻断外发：网络层拦截（不依赖应用配合）
        ↓
【③ 引导】引导走正确出口：提示「该数据应走 X 出口」，引导到合规通道
```

### 密钥管理（凭据防护）

```
访问敏感凭据
   ↓
【① 判定】凭据访问：这次读取是否触达 .env / 密钥 / 证书？
   ├─ 非敏感 → 放行
   └─ 敏感 → 进入熔断+引导
        ↓
【② 熔断】阻断明文读取：凭据不落盘，只给临时令牌
        ↓
【③ 引导】引导走安全通道：自动脱敏 + 短时令牌（不是让 Agent 拿不到，而是拿「该拿的」）
```

**为什么「引导」是关键**：

> 简单熔断 = Agent 需要凭据时直接失败 → 业务中断；
> 引导 = Agent 拿到「脱敏后的临时令牌」→ 业务继续，凭据不泄露。

## 三、技术落地点

| 环节 | 能力 | 复用 |
|---|---|---|
| ① 判定 | egress 意图识别 + 敏感凭据访问识别 | 参数闸门 + 语义免疫 |
| ② 熔断 | 网络出口白名单 + 凭据不落盘 | **CO-OS 内核态**（进程级拦截，应用绕不过） |
| ③ 引导 | 合规出口路由 + 凭据自动脱敏/短时令牌 | 回锚机制（`re_anchor`） |

**示例**：

```
场景：Agent 要把内部合同上传到「个人网盘」（不在白名单）
   ↓ ① 判定：egress 意图命中，目标不在白名单
   ↓ ② 熔断：网络层阻断上传
   ↓ ③ 引导：提示「应上传到企业 OSS」，并路由到合规出口
```

## 四、产品形态

1. **CO-OS 增强**：内核态 egress 白名单（网络出口进程级管控）+ 凭据脱敏钩子；
2. **SDK 增强**：`param_guard` 增加「凭据自动脱敏」——检测到 .env/密钥访问时，返回脱敏值而非原文；
3. **配置化白名单**：egress 出口 + 敏感路径，全部通过 `config.json` 声明，无代码接入。

## 五、与现有能力的关系

```
七层纵深里的「⑥ 环境层」深化：
  之前：CO-OS 内核熔断（通用阻断）
  现在：egress 白名单 + 凭据脱敏（精准兜底）

治理理念的三层贯穿：
  行为链（判）→ 熔断（拦）→ 回锚引导（引）
  └─ 环境层同样贯彻「引导」：不是让数据出不去，是让数据走对出口
```

**一句话**：egress + 密钥管理，让星环从「应用层拦截」升级到「内核态物理兜底 + 安全通道引导」——这是「系统级底牌」的完整兑现。
