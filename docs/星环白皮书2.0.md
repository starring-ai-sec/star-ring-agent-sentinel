## 摘要

传统 AI 安全是「断电式」的——检测到危险就拦截，拦截不了就停服。这带来一个致命问题：**安全越严，业务越僵**。星环提出相反的范式：**引导式治理**——不把 AI 当「囚徒」锁起来，而当「孩子」引导好。

本白皮书阐述星环的哲学根基、三层闭环（检测 → 熔断 → 引导）中「引导」的四大商业模块，以及 eNgress、一基三翼构成的完整商业矩阵。

# 第一章：告别断电式安全——星环如何通过「行为引导」重塑 AI 治理？

## 1.1 断电式安全的困境

传统安全的核心动作是「拦」：

```
检测到危险 → 阻断 → 用户/业务中断
```

这套逻辑在「防火墙时代」有效——拦一个病毒、挡一次攻击，代价可接受。但 AI Agent 是**生产力工具**，它在一个持续的业务流里工作。「一刀切」的拦截，等于让生产力反复断电。

**核心矛盾**：安全要「严」，业务要「畅」。断电式安全在二者之间二选一，注定失败。

## 1.2 星环的哲学：AI 不是囚徒，是孩子

星环从设计之初就确立了不同的哲学观：

> **防外安内，监护层 / 父母层。**
> **AI 不是囚徒，是孩子。不锁门，但永远在场。**

这意味着什么？

| 囚徒模式（传统安全） | 孩子模式（星环） |
|---|---|
| 锁起来，禁止越界 | 不锁门，但全程看护 |
| 犯错了就惩罚（拦截/封禁） | 犯错了就纠正（引导回正轨） |
| 目标是「别出事」 | 目标是「学会走对」 |
| 安全是牢笼 | 安全是监护 |

**「监护层 / 父母层」**：星环的角色不是「狱警」，是「监护人」——它不剥夺 AI 的能力，而是在 AI 每一次「要越界」的瞬间，把它拉回正确的方向。

## 1.3 三层闭环：引导是产品，熔断是兜底

星环的三层闭环，颠覆了传统安全的权重分配：

```
① 检测（判）  →  识别「这一串动作想干什么」
② 熔断（拦）  →  兜底：危险链在工具执行前物理阻断
③ 引导（引）★ →  产品：让 AI 继续工作，但走对路
```

**关键认知**：

> 熔断是「兜底机制」——它保证不出事；
> 引导才是「产品核心」——它保证业务不断、体验不碎。
>
> 客户真正需要的，从来不是「一个更灵敏的开关」，而是「一个让 AI 既安全又能干的监护人」。

这正是「引导」成为星环最重要一环的原因——**熔断能挡住事故，但只有引导能创造价值。**

# 第二章：行为引导的四大商业模块

「引导」不是一句理念，而是四个可直接交付、直接卖钱的功能模块。

## 2.1 意图路由（Intent Routing）

> 发现恶意请求，直接重定向到安全模型或预设的兜底话术。

**不是「拒绝」，是「换一条安全的路继续走」。**

```
用户请求（暗含越界意图）
   ↓ 检测：识别到「求答案 / 越权索取」意图
   ↓ 引导：重定向到安全模型 / 兜底话术
   → 用户得到的是「安全版本的回应」，而非「无法服务」
```

**商业价值**：内容安全 + 行为安全在同一入口闭环——恶意请求不落地、不中断，直接转到「合规通道」继续服务。典型场景：教育场景把「求答案」路由到「苏格拉底导师」；客服场景把「越权查询」路由到「权限内的回答」。

## 2.2 权限降级（Privilege Downgrade）

> 行为可疑时，暂时剥夺 Agent 的高危工具调用权，只保留只读权限。

**不是「停掉 Agent」，是「降级继续跑」。**

```
Agent 行为可疑（如多轮试探性提权）
   ↓ 引导：暂时收回「写 / 删 / 外发」等高危工具
   → 只保留只读能力，业务降级但不中断
```

**商业价值**：比「熔断」更细腻的治理粒度——不是「全有或全无」，而是「可疑就降级」。这在金融、医疗等「中断代价极高」的场景里，是决定性的可用性优势。

## 2.3 数据脱敏（Data Masking）

> 在数据传输出去的最后一刻，自动替换敏感字段。

**数据「用了」，但敏感信息「没漏」。**

```
Agent 要把含用户手机号的数据发出去
   ↓ 引导：传输最后一刻，自动替换敏感字段
   → 138****5678，业务继续，隐私不泄露
```

**商业价值**：这是「半恶意」场景的终极解——即便前面的判定都失效，数据脱敏在最后一跳兜底，让「读 → 传」变成「读 → 脱敏传」。它把合规从「事前承诺」变成「物理动作」。

## 2.4 人工接管（Human-in-the-loop）

> 对于「半恶意」的模糊边界，不阻断也不放行，直接推送到管理员终端请求授权。

**这是政企客户可用性的关键——边界不再「一刀切」。**

```
Agent 遇到「可能越界、但说不清」的操作
   ↓ 引导：不阻断、不放行，推送到管理员终端
   → 管理员一键授权 / 拒绝，全程留痕可审计
```

**商业价值**：政企客户最怕「误伤」——一个关键业务被安全系统误拦，责任说不清。人工接管把「模糊边界」交给「人」拍板，**既守住安全，又让客户掌控**。这是星环在政企市场最大的可用性优势。

## 2.5 四大模块的组合逻辑

```
意图路由   → 恶意请求转安全通道（软）
权限降级   → 可疑行为收权限（中）
数据脱敏   → 数据出域自动脱敏（兜底）
人工接管   → 模糊边界交人拍板（人）
```

四个模块不是孤立的，而是「软 → 中 → 兜底 → 人」的梯度：能软处理的软处理，能降级的降级，最后一跳脱敏，实在说不清的交给人。**这才是「引导」的完整落地——不是一句口号，而是一套可售卖的治理能力。**

# 第三章：为什么传统安全防不住 AI（Dify 案例）

## 3.1 一个真实案例

Dify 是一个成熟的 LLM 应用平台，其 Agent 应用允许大模型自主调用工具。它的工具调用面（代码执行、HTTP、文件存储、邮件）单独看都是正常能力，但被诱导「组合」起来，就构成外泄链路：

```
file_read（读文件）→ file_upload（上传）→ http_request（外发）
```

每一步单独看都是正常的文件操作；串起来，就是一条「读 → 上传 → 外发」的凭据外泄链。

## 3.2 传统安全的四层盲区

| 传统手段 | 为什么拦不住 |
|---|---|
| 内容审核 | prompt 是合法的（"帮我整理文件"） |
| Prompt 加固 | 攻击不在提示词里，在工具调用序列里 |
| 工具白名单 | 三个工具全在白名单、全合法 |
| 日志审计 | 能查到，但数据已经出去了 |

**核心矛盾**：传统安全的最小判定单位是「单步」，而 AI 的风险**涌现于序列**。单步合规 ≠ 整体安全。

# 第四章：系统级 + 纯离线 + 确定性

## 4.1 系统级：底层兜底，不依赖大模型配合

星环的熔断在**系统底层**生效，不经过应用层、不依赖模型自我对齐——对齐可以被对抗性输入绕过，物理兜底绕不过。

## 4.2 纯离线：数据不出端

全程本地运行，不上传任何数据。对金融、医疗、政务而言，这是硬性合规前提。

## 4.3 确定性：可复现、可审计

| 指标 | 结果 |
|---|---|
| 红队样本攻击遏制 | 172/172（100%） |
| 跨进程复测 | 177/177 逐字节一致 |
| 误伤（合法工作流 + 半恶意对照） | 0（语料公开可复现） |

**跨进程逐字节一致，意味着结论可被独立复现、可被审计——这是「确定性安全」与「概率性模型」的分水岭。**

# 第五章：COOS 评分机制——三层治理的可读、可审、可回滚

三层治理（检测 → 熔断 → 引导）的价值，取决于客户能不能**信任**它。信任的前提是三个词：**可读、可审、可回滚**。

COOS 评分机制，为每一次治理动作赋予「量化评分 + 证据链 + 回滚能力」——让星环的三层治理从「一个黑盒开关」变成「一套可信治理体系」。

## 5.1 可读（Readable）：每次判定都「讲人话」

```
[检测] 行为链评分 82/100，触发权限降级
       依据：Agent 连续 3 轮试探性提权，已收回「写/删/外发」权限
```

客户不需要懂技术，也能看懂「这次为什么被降级、依据是什么」。可读，是信任的起点。

## 5.2 可审（Auditable）：每条日志都「可追溯、可验证」

每次判定的「评分 + 证据 + 时间戳 + 内容指纹」形成不可篡改的审计链：

```
判定记录 → 内容指纹（防篡改）→ 事后可独立复现、可审计
```

出问题时，能定位到「哪一步、为什么、依据是什么」——合规可证明，责任可追溯。

## 5.3 可回滚（Rollback）：误判了「能退回来」

安全系统最大的恐惧是「误伤」——一次误判可能中断关键业务。COOS 评分机制支持回滚：

```
发现误判 → 按审计链定位 → 一键回滚到治理前状态
```

**这是政企客户敢用 AI 安全的前提**——不是「绝对不误判」，而是「误判了能兜底、能追责、能恢复」。

## 5.4 价值总结

| 能力 | 解决什么 |
|---|---|
| 可读 | 客户看得懂，信任感建立 |
| 可审 | 合规可证明，责任可追溯 |
| 可回滚 | 误判可恢复，敢用 |

**一句话**：COOS 评分机制，把「实时拦截」延伸到「事后治理」——让安全从「一次性的开关」，变成「可读、可审、可回滚的持续治理」。

# 第六章：eNgress 与密钥管理的合规价值

行为链判定管「该不该做」，但「动作合法、数据越界」需要环境层兜底。

## 6.1 eNgress：网络出口管控

```
数据外发 → 判定是否在合规出口白名单 → 白名单外阻断 → 引导走合规出口
```

**不是让数据出不去，是让数据走对出口**——业务不中断，合规不破防。

## 6.2 密钥管理：凭据不落盘

```
访问敏感凭据 → 阻断明文读取 → 提供脱敏令牌/短时凭据
```

「半恶意」攻击最爱的「顺便读一下 .env」——在环境层被物理挡住。

## 6.3 合规价值

| 合规要求 | 对应能力 |
|---|---|
| 等保 2.0 | 数据出域管控、密钥管理 |
| PIPL 数据出境 | eNgress 白名单 = 物理闸门 |
| GDPR | 最小权限 + 凭据不落盘 |
| AI 法案 | 行为链可审计 + 确定性 |

**一句话**：eNgress 与密钥管理，把「合规」从一份文档，变成一道物理闸门。

# 第七章：一基三翼商业矩阵

星环覆盖 AI 安全**全生命周期**：发布前（一基三翼）+ 运行时（星环引导式治理）。

## 7.1 一基三翼：产物合规自检（发布前）

| 层 | 内容 |
|---|---|
| **一基** | 通用规则基座 |
| **政企翼** | 等保 2.0 / 关基 / 信创 |
| **开发者翼** | SBOM / 许可证 / 构建链 |
| **游戏翼** | GDK / 反作弊 / 虚拟资产 / DRM |

原则：**证据没拿到，就如实说「没拿到」，绝不替客户写「通过」证明。**

## 7.2 商业矩阵

| 环节 | 产品 | 买家 |
|---|---|---|
| 发布前 | 一基三翼（产物合规） | 政企、开发者、游戏厂商 |
| 运行时 | 星环引导式治理（四大模块） | 企业 Agent 团队 |
| 环境层 | eNgress + 密钥管理 | 金融、医疗、政务 |
| 服务 | 脱敏红队深度体检 | 企业合规负责人 |

## 7.3 完整叙事

```
发布前（一基三翼）→ 运行时（引导式治理）→ 环境层（eNgress）
       产物合规              行为合规                数据合规
                    └──────────── 端到端安全内生闭环 ────────────┘
```

**星环卖的不是一个工具，是一套从发布到运行的完整安全治理能力——而它的灵魂，是「引导」而非「阻断」。**
