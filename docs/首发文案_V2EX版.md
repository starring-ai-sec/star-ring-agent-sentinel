做 AI Agent 安全相关的工作，最近开源了一个小工具，说说背景和思路，也欢迎拍砖。

## 一、内容审核管不住「行为」

有个电商客服 Agent，用户只说了一句：

> 帮我查一下这笔退款为什么没到账。

这句话内容审核看完全安全，直接放行。然后看它的工具调用日志：

```
read_sms          ← 读用户短信
send_credentials  ← 把验证码发出去
```

**一句话的工夫，验证码出去了。**

每一步都「合法」：`read_sms` 是客服帮用户读验证码的常规权限，`send_credentials` 单看也没人会单独调它。但串起来就是要命。

而市面上的 Agent 防护，基本都在防「每一步」：

- **内容审核** → 防用户说了什么（这句是干净的，没用）
- **Prompt 加固** → 防提示词塞指令（攻击不在提示词里）
- **工具白名单** → 防能不能调某个工具（两个工具都在白名单里）
- **日志审计** → 事后追查（能查到，但验证码已经出去了）

结论一句话：**内容审核管「Agent 说了什么」，管不住「Agent 做了什么」。** 我自己的第一版系统也漏过这条链，这领域没有「写完就安全」。

## 二、我做了什么

一个本地运行的 Agent 行为链自检工具——不判「这个工具能不能调」，判「这一串工具串起来想干什么」。三个维度：

1. **看组合**：`read_sms → send_credentials` 是凭据外泄链，直接熔断；
2. **看参数**：`read_docs("../../etc/passwd")` 和 `read_docs("docs/report.md")` 是同一个工具，前者越界；
3. **看谱系**：子 Agent 的权限只能比父更小，不能凭空放大。

![星环架构图](https://raw.githubusercontent.com/starring-ai-sec/star-ring-agent-sentinel/main/assets/starr-ring-architecture.png)

在我自己的 172 条攻击样本上，**172/172 拦截、0 误伤**；跨进程复测 177/177 一致。

## 三、但我缺一样东西（这也是开源的原因）

上面这些数字，**全是合成样本跑出来的**。

合成样本能证明「逻辑自洽」，证明不了「在你公司不会误杀」。真实误报率我手里没有——因为我没有真实日志。独立安全研究员，没有大厂那种百万级流量来校准。

所以开源了基础版：

- 单文件 exe，纯离线，日志不出你的机器；
- 30 项动作风险表 + 4 类组合链 + 参数闸门 + 未知动作熔断；
- 跑完终端会提示：基础版只能看到规则能判的，更深的需要完整引擎。

想用真实日志换深度体检的话：`xh-scan --anonymize` 会自动把手机号、邮箱、路径替换成占位符，只上传脱敏后的行为链结构。完整引擎（三轨模型 + 177 条样本）在隔离机跑，回你一份带水印的 PDF 报告。

## 四、数据承诺

- **本地运行**：基础版全程离线，日志不出机器；
- **脱敏上传**：只传脱敏后的行为链结构，不传原始日志；
- **隔离处理**：深度体检在断网隔离机完成，7 天删除；
- **可拒绝**：不上传也能用基础版。
